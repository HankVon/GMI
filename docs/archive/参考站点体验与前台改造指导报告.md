# GMI 前台数据产品改造指导报告

## 1. 目标与原则

本次改造面向 `/site`、`/site/data-center/*` 与 `/site/intelligence*` 前台页面。参考建设通的页面组织方式，但不复制其会员限制和品牌内容：保留 GMI 的真实数据、单位/人员/项目关联、Neo4j 人脉路径、AI 研判、动态字段和数据流水线能力。

核心原则：

- 先让用户看懂数据，再让用户执行筛选、订阅、导出、跟进和关联跳转。
- 列表页承担发现与比较，详情页承担核验与行动。
- 所有统计数字必须对应真实接口；空字段显示“未披露”，不伪造业务事实。
- 前台详情与后台详情使用同一数据契约，但编辑、补全、删除等管理动作只在工作台出现。
- 详情返回应回到用户刚才的列表和筛选上下文，直接访问时提供稳定兜底路由。

## 2. 参考页面拆解

### 2.1 首页 `/site`

参考首页的有效信息层级是：品牌与搜索入口、功能导航、最新动态、数据更新提示、热门主体/项目、数据总量。GMI 当前首页已经有搜索、快捷入口、最新中标/意向/单位、排行榜、统计图表和 AI 能力说明，因此改造重点是：

- 搜索对象与目标页面保持一一对应：标讯、单位、人员、意向。
- 最新动态使用统一的信息行结构：日期、类型、标题、主体、地区/金额。
- 统计和更新时间放在数据流附近，避免让用户误以为是静态宣传数字。
- 保留 GMI 的图谱、AI、线索监测优势，但降低装饰性背景对信息阅读的干扰。

### 2.2 招投标列表 `/site/data-center/overview`

参考列表页由以下闭环组成：

1. 标讯类型切换：全部、招标、中标/成交、变更等。
2. 关键词、地区、时间范围筛选。
3. 数据总量与活跃采购人/供应商聚合。
4. 立即订阅、已保存订阅、导出当前结果。
5. 单条卡片：类型、发布时间、标题、项目编号、金额、地区、采购人、代理机构、中标供应商、截止提醒。
6. 分页和页码跳转。

GMI 已具备 1 至 6 中的大部分能力。需要确保：

- 前台路径显示的是标讯列表，而不是后台“项目管理”语义。
- 列表和详情跳转统一使用 `/site/data-center/projects/:id`，兼容已有 `/bids/:id`。
- 卡片字段优先取 `BidNotice.meta` 中的结构化字段，缺失时稳定显示“未披露”。
- 导出与订阅必须沿用当前筛选条件；导出失败需要给出明确提示。

### 2.3 招投标详情 `/site/data-center/projects/:id`

参考详情页的信息分组：

- 标题、公告类型、来源、发布时间和操作区。
- 基本信息：项目编号、地区、采购人、代理机构、招标方式、项目分类。
- 关键时间：报名截止、文件获取截止、投标截止、开标、计划开工/竣工。
- 资金信息：项目金额、预算/控制价、保证金、资金来源、付款方式。
- 评标信息：评标办法、专家/分值、定标方式。
- 资质业绩：企业资质、人员资质、业绩要求、联合体要求。
- 公告正文和附件。
- 关联单位、相似项目、监控/收藏/原文入口。

GMI 已经有结构化字段渲染和供应商关联，本次重点是使用真实 `timeline` 字段，增加可回退的监控/收藏状态，并修复前台单位跳转前缀。

### 2.4 单位详情 `/site/data-center/companies/:id`

参考业主页强调工商速览、联系方式、经营范围、项目数据和合作关系。GMI 现有 `CompanyDetail.vue` 已覆盖：工商信息、项目、人员、资质、荣誉、诚信、风险、开标、人脉路径、意向关联、AI 分析和编辑权限。改造原则是只调整前台路由上下文和返回行为，不破坏工作台管理动作。

### 2.5 人员详情 `/site/data-center/persons/:id`

参考人员页强调姓名/职位/所属单位、基本资料和参与项目列表。GMI 已有人员速览、证书、项目轨迹、合作单位、人脉路径和 AI 分析。前台只需确保页面在 PortalLayout 中正确返回人员列表，并隐藏编辑/退出等管理行为。

### 2.6 情报列表 `/site/intelligence`

参考项目商机页的有效结构：行业、阶段、地区、金额档位等多维筛选；列表突出投资金额、业主、项目阶段和更新时间；详情可继续查看生命周期和联系人。

GMI 当前列表已具备时间、行业、阶段、地域、关键词、热度、合作概率、业主和图谱。改造验收重点：

- 筛选字段标签与实际字段一致，行业使用 `project_type/industry` 的清晰映射。
- 列表卡片突出金额档位、项目阶段、地域和发布单位。
- 情报总数、覆盖地域、平均热度等统计随数据变化。
- 详情跳转走 `/site/intelligence/:id`，关联单位可继续进入单位画像。

### 2.7 意向详情

参考详情页按“项目概况、投资金额、资金来源、建设周期、阶段、描述、联系人、来源、智能分析”组织。GMI 已有正文结构化解析、附件、人脉触达路径和 AI 缓存/异步生成能力；需保持缓存优先、生成失败可回退，不因 AI 服务不可用阻塞基础数据阅读。

## 3. 数据契约与功能归属

| 用户动作 | 前台归属 | 后台/接口能力 |
|---|---|---|
| 搜索标讯 | 首页、标讯列表 | `GET /bids` |
| 筛选标讯 | 标讯列表 | `keyword/province/notice_type/date_*` |
| 保存订阅 | 标讯列表 | 浏览器本地订阅，后续可替换为账号订阅 |
| 导出标讯 | 标讯列表 | 客户端 CSV；管理端保留 Excel 导出 |
| 查看公告结构 | 标讯详情 | `GET /bids/:id` |
| 查看单位多维画像 | 单位详情 | `GET /companies/:id/*` |
| 查看人员与参与项目 | 人员详情 | `GET /persons/:id`、轨迹接口 |
| 发现意向商机 | 情报列表 | `GET /public/intelligence` |
| AI 研判与人脉路径 | 意向/单位/人员详情 | AI、Neo4j 相关接口 |
| 编辑、删除、导入、补全 | 工作台 | 仅保留在非 Portal 模式 |

## 4. 本次落地改造

- 统一标讯详情路径，保留旧路径兼容。
- 后端标讯详情补充来源、结构化时间、附件和阶段字段的稳定归一化。
- 标讯详情使用真实时间节点；无数据时显示未披露，不使用占位日期冒充事实。
- 增加详情页监控/收藏本地状态和列表筛选回退。
- 优化首页与数据中心跳转的 query 语义，确保关键词和 tab 可恢复。
- 保持单位、人员、情报详情已有真实数据和 AI/图谱能力。

## 5. 验收标准

- 7 个目标地址均能加载，不出现空白或错误路由。
- 首页搜索能够将关键词带入对应列表。
- 标讯筛选后总数、列表、导出结果使用同一组条件。
- 从列表进入标讯/单位/人员/意向详情后可返回原上下文。
- 标讯详情的关键时间、资金、评标、资质业绩模块按数据存在性展示。
- 单位与人员前台不出现编辑、删除、补全等管理操作。
- AI/图谱接口失败时，基础内容仍可阅读。
- `npm run build` 通过，后端 Python 文件可编译。
