内部评级：🔧 无信用评价业务可省；如需保留"企业+等级+时间"三字段。

### 3.9 查业主（383 万）✅直接借鉴（高价值）

**筛选条件**（建设通最精细的查询表单）：
- 基础：业主名称/经营范围/合作企业/常发包项目
- **发包规模**：上年度发包总额(区间) + **金额市级排名(前10/20/50/100)** + 发包数量 + **数量市级排名** + 含子公司统计
- 项目属性：专题/资金来源/发包类型/投资类型/经济类型
- 地区：注册地区/经营地区
- 工商：注册资本(区间)/成立年限/是否上市/企业类型

内部评级：✅ **"发包总额+排名"统计口径对内部客户经营极有价值**，基于 bid_notice 聚合即可；成立年限/注册资本筛选复用内部字段。

## 12. 技术栈实现方案（内部版）

### 12.1 建设通实际技术栈（实证参照）

| 层 | 技术 | 证据 |
|---|---|---|
| 前端 | Nuxt2 SSR + Vue2 + Element UI + ECharts + webpack | SSR 标记 + Element UI 源码反编译 |
| 后端 | ASP.NET 多子域微服务（passport/user/vip/jst/sj/jstbid） | `x-powered-by: ASP.NET` + Controller 风格接口 |
| 搜索 | Elasticsearch（推断） | 3000 万级多条件筛选 |
| 存储 | SQL Server/MySQL + Redis | 接口与缓存特征 |
| 安全 | 网易易盾 + FingerprintJS + 参数加密 | 登录实测 + 请求头分析 |
| 统计 | 百度统计 | hm.js |

### 12.2 内部版技术栈（基于 GMI 现状）

| 层 | 技术 | 理由 |
|---|---|---|
| 前端 | Vue3 + Vite + Element Plus + Pinia + ECharts + TS（已有） | 内部无 SEO/SSR 诉求，SPA 迭代最快 |
| 后端 | FastAPI（已有） | Python 生态与 LLM(Ollama)/爬虫(crawl4ai) 无缝衔接 |
| 数据库 | MySQL（已有）+ Redis（已有）+ Neo4j（已有） | 人脉图谱/同场竞标依赖图查询 |
| 搜索 | Elasticsearch（可选后加） | 万级先用 MySQL 虚拟列过渡 |
| 采集 | crawl4ai 单实例串行 + apscheduler（已有） | 新源只加配置 |
| 部署 | Docker Compose（已有）+ 内网 + 现有隧道 | 单机即可跑通 |

**关键选型理由**：
1. 不复制 .NET/Nuxt：内部非公网门户，Vue3+FastAPI 研发效率与 AI 生态占优
2. 订阅引擎放后端定时任务 + Redis 去重：与入库同链路，防重复推送
3. 脱敏走字段级权限而非"打码→付费"：内部用角色控制
4. 竞争企业分析放 Neo4j：同场竞标关系本质是图查询
5. 搜索用 MySQL 虚拟列起步：数据量上来再双写 ES
