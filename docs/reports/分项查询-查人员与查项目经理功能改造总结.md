# 分享查询「查人员 / 查项目经理」功能改造总结

> 生成日期：2026-08-31
> 范围：官网「分项查询（SubQuery）」新增人员查询能力、相关后端接口增强、若干缺陷修复与体验优化。

---

## 一、概述

本期工作围绕官网「分项查询」页（路由 `SiteSubQuery`，组件 `SubQuery.vue`）展开，核心是**新增「查人员」「查项目经理」两个查询 tab**，打通从筛选、列表到人员详情的端到端链路；并顺带修复/优化了若干影响体验的缺陷（构建阻塞、人员详情 404、404/403 返回后台、详情页名称重复）。

所有改动均保持与既有「查企业」能力一致的风格与权限模型（登录态接口、站点布局、`.sq-*` 主题变量）。

---

## 二、主要完成的任务

### 1. 分享查询新增「查人员 / 查项目经理」

- 新建独立组件 `PersonSubQuery.vue`，通过 `mode` prop（`"person" | "manager"`）**一套逻辑复用两种模式**：
  - `person`：标签为「查人员」，默认职位为空。
  - `manager`：标签为「查项目经理」，默认职位填「项目经理」，搜索框 placeholder 差异化。
- 在 `SubQuery.vue` 的 tab 栏接入：点击对应 tab 即渲染 `PersonSubQuery`，挂载时自动检索；其余未实现 tab（查业绩/资质/荣誉/诚信/信用评价/业主/开标记录）走占位 + `ElMessage.info` 提示。
- 人员详情跳转落在站点侧路由 `/site/data-center/persons/:id`（`DataCenterPersonProfile`），与企业详情 `/site/data-center/companies/:id` 保持一致。

### 2. 后端 `/persons` 列表接口增强（`list_persons`）

- 新增三个查询参数：
  - `province`：按所属单位所在省份筛选。
  - `company_keyword`：所属单位名称模糊匹配。
  - `position`：职位关键词模糊匹配（`Person.position.contains`）。
- 单位维度筛选时 `join(Company, Company.id == Person.company_id)` 并拼 `where(*company_conds)`；无单位条件时不 join，不影响原查询与性能。
- 完整保留既有能力：`resolve_scope / scope_filter` 数据范围权限、通用 `filters` JSON 多值筛选、动态字段排序，仅做向后兼容的增量追加。
- 列表字段补齐（批量查询，避免 N+1）：
  - 一次性 `Company.id.in_(cids)` 取单位名 / 省 / 市。
  - 一次 `ProjectMember join Project` 按 `person_id` 分组取参与项目（按 `created_at desc`），首条作为 `latest_project_time`，项目名用「、」拼接为 `related_projects`。
- Schema `PersonResponse` 新增 5 个展示字段：`company_name / company_province / company_city / latest_project_time / related_projects`（均为 Optional，默认 None）。

## 三、技术实现方式（要点）

- **前端组件化**：`PersonSubQuery.vue` 负责筛选区、结果列表、分页、姓名高亮、跳转；`SubQuery.vue` 仅做 tab 编排与占位。
- **关键词高亮防 XSS**：姓名高亮前先 `escapeHtml` 转义，再做正则替换，避免注入。
- **省份归一化**：后端 `persons.py` 引入 `app.services.china_regions.province_core`，用 `Company.province.like("%核心%")`，兼容库内"四川"与"四川省"两种写法，与 `companies.py` 口径对齐。
- **参与项目截断**：`related_projects` 超过 3 个时显示「前 3 个 + 等 N 个」，避免列表行过长。
- **站点上下文导航**：`useNavBase().navTo` 按当前路由前缀（`/site/data-center` 或 `/workspace`）自动拼接跳转前缀，站点内跳转保持闭环。
- **404/403 上下文感知**：基于 `route.path.startsWith("/site")` 区分站点/后台，分别回数据中心首页或工作台，避免站点访客被引向后台登录。

## 六、待处理事项与后续建议

1. **其余 7 个 tab 仍为占位**（查业绩 / 查资质 / 查荣誉 / 查诚信 / 信用评价 / 查业主 / 开标记录），是否继续建设待产品决策。其中「查项目经理」已复用人员能力，可优先；「查业绩」可基于现有项目数据扩展。
2. **公开接口（可选）**：当前「分项查询」走登录态接口（`/persons`、`/companies`）。若未来要面向未登录访客开放，需将查企业 + 查人员一并改造为 `/public/*` 公开接口并做字段脱敏（如姓名掩码），当前二者保持一致的预期行为即可，无需单独为人员做公开化。
3. **`related_projects` 取值口径**：目前取的是 `ProjectMember` 关联的全部项目（不限项目状态/地域），若只想体现「目标地域内项目」可后续按 `china_regions.is_target_province` 过滤。
4. **构建分包优化（非阻塞）**：`echarts`、`index` 主包超过 500KB 触发告警，可后续用 `manualChunks` 或动态 import 拆分，与本次功能无关。
