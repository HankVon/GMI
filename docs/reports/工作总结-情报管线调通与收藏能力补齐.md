## 二、涉及的功能模块

- **后端**
  - `app/services/intent_crawler.py`：抓取主逻辑、字段抽取（金额/联系人/地域/部门/业主）、目标省份过滤。
  - `app/api/v1/favorites.py`：收藏 API（`toggle / state / summary / list`），本轮扩展 opportunity 支持。
  - `app/services/scheduler.py`：定时任务注册（意向抓取 / 人脉重建 / GEO 监测 / 过期清理等）。
  - `app/api/v1/opportunities.py`：商机建档（intent → opportunity 映射，幂等）。
  - `app/services/intent_quality.py`：发布质量闸门 `can_publish()`。
  - `app/services/china_regions.py`：省-市-县三级行政区划库（川藏新权威来源）。
  - 模型：`IntentNotice`、`Opportunity`、`Favorite`。
- **前端**
  - `OpportunityList.vue`：商机列表新增「收藏」列。
  - `AccountCollection.vue`：个人中心「我的收藏」新增「商机」标签与计数。
  - `FavoriteButton.vue`：通用收藏/标签组件（复用）。
- **数据与配置**
  - `web_source`（id=147 西藏矿业权出让源）、`opportunity`（145）、`intent_notice`（195）。
  - `requirements.txt`：含 `apscheduler==3.11.3`（已在本环境安装）。

## 三、技术实现方式

- **抓取**：`httpx` 静态抓取 + `crawl4ai` 渲染回退；详情链接正则兼容发改委/自然资源厅/公共资源交易平台（含 `.jhtml` 与 `window.open` 写法）；正文清洗去导航/面包屑/表格保序。
- **结构化抽取**：以正则为主（金额/联系人/地域/部门/项目业主），`knowledge_extractor`（LLM）辅助；地域经 `china_regions` 做省-市-县三级归一与川藏新目标省份过滤。
- **发布闸门**：`can_publish()` 以必填字段（发布部门/地域）阻断、加分项（金额/联系人/开工时间/关联单位）仅警告。
- **收藏模型**：`favorite` 表 + `/favorites` 系列接口；个人中心按 `entity_type` 分标签展示，名称经实体表解析（商机兼容 `project_name`）。
- **定时任务**：`APScheduler` cron 每日 03:00 执行 `_job_crawl_intents` → 推理侦察（`opportunity_scout`）→ 项目跟踪（`project_tracker`），随 FastAPI 启动/关停。
- **数据回填**：采用**原生 SQL**脚本（规避本开发环境 Python 3.14 与 SQLAlchemy 的 ORM 模型类定义兼容问题），仅填充 NULL 字段、绝不覆盖已有人工策展数据。

## 五、待处理事项 / 已知限制

1. **金额/联系人覆盖率**：受限于 `intent_notice.raw_text` 为摘要文本（不含完整金额/联系人），本轮回填后仍有部分 NULL。需后续接入**附件解析**或存储全文正文，才能进一步提升覆盖。
2. **地域精度**：部分西藏矿业权公告仅标注「西藏自治区」未标注具体地市，`region_city` 维持省份级，属数据源限制。
3. **非核心草稿策略**：非川藏新业务草稿按既定策略保留、不主动发布；如需放开需业务方确认。
4. **运行环境**：本开发环境为 Python 3.14，与 SQLAlchemy 存在 ORM 模型类定义兼容问题（仅影响本机脚本/ORM 导入，不影响 docker/Python 3.11 正式运行）；运维类脚本统一使用原生 SQL 以规避。
