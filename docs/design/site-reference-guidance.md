# GMI 官网数据产品改造指导报告

> 调研日期：2026-08-27
> 
> 参考站点：建设通首页、AI 标讯列表/详情、业主详情、联系人详情、项目商机列表/详情。

## 1. 改造目标与边界

GMI 不直接复制参考站点的品牌、文案或数据，而是借鉴其成熟的信息组织方式，将现有的招投标、单位画像、人员关系、意向情报和 AI 分析能力组织为连续的数据工作流：

`发现入口 -> 条件检索 -> 结构化详情 -> 关联主体 -> AI 研判/行动`

现有产品优势必须保留：

- 公开数据采集与数据流水线能力；
- 单位、人员、项目之间的关联关系和人脉路径；
- 意向情报的规则/大模型双路分析；
- 面向官网的公开接口与脱敏展示；
- 后台可编辑、进展维护、字段扩展能力。

统一视觉建议：浅色机构风，酒红作为主行动色，蓝色表示链接与关系，绿色表示有效/最新，暗金表示金额或重点标签。页面信息优先级应通过标题、数据标签、时间和关联入口表达，不使用营销式大幅留白遮挡核心数据。

## 2. 参考站点共性逻辑

### 2.1 全局导航

参考站点将服务分成分项查询、行业/地区专查、高级查询、商机会员、AI 标讯和研究服务。GMI 对应为：

- 数据中心：标讯、项目、单位、人员；
- 情报动态：意向信息和项目商机；
- 人脉网络：单位/人员/项目关系；
- 后台工作台：流水线、字段、权限、审计。

官网顶栏应提供对象级入口，详情页提供“返回列表”“查看关联单位/人员/项目”闭环。

### 2.2 权限与数据完整性

参考站点对联系人、招标文件、财务、融资、合作关系等内容做权限控制。GMI 当前以公开接口、脱敏提示和 AI 说明为主，不能伪造不存在的数据。所有缺失字段使用“未披露/暂无数据”，并在详情页给出来源、更新时间和数据说明；需要登录或后台权限的操作复用现有路由守卫与 `isPortal` 模式。

### 2.3 状态反馈

列表和详情均应具备加载中、空数据、请求失败、筛选无结果、导出中、订阅保存成功等状态。查询条件变化后重置页码；详情返回列表时保留 Tab、筛选和滚动位置。

## 3. 首页 `/site`

### 参考结构

1. 顶部品牌、对象级导航、登录/注册/进入数据中心；
2. 主搜索：对象 Tab + 关键词 + 搜索按钮；
3. 高频入口：标讯、单位、人员、项目商机、公开检索；
4. 数据更新标签：更新时间、覆盖范围、今日新增；
5. 最新信息流：最新中标、最新招标/标讯、意向公告、单位更新；
6. 数据统计：覆盖单位、项目、人员、标讯、网页线索；
7. 活跃单位/地域排行；
8. GMI 差异化区：AI 研判、人脉网络、数据流水线和实时图表。

### 交互逻辑

- 搜索 Tab 决定目标对象和后续路由；
- 动态 Tab 只切换数据源，不丢失页面状态；
- 点击标题进入详情，点击单位进入单位画像；
- 数字指标可进入对应列表；
- 更新标签显示真实 `updated_at`，无数据时使用明确占位。

### 现状与改造

现有 `Home.vue` 已有搜索、快捷入口、动态 Tab、排行榜、图表和能力矩阵。优先调整信息层级与入口文案，保留图表、AI、人脉和采集能力，不新增没有后端来源的虚假指标。

## 4. 招投标列表 `/site/data-center/overview`

### 参考字段顺序

`项目名称/编号 -> 类型/行业 -> 报名及投标截止 -> 金额 -> 地区 -> 招标单位 -> 招标代理 -> 发布时间`

### 必备模块

- 页面标题与平台定位；
- 关键词检索；
- 公告类型 Tab：全部、中标、成交、招标、其他；
- 地区、日期范围、采购人、供应商筛选；
- 搜索结果总量和活跃采购人/供应商 Top；
- 当前筛选条件标签；
- 立即订阅、我的订阅、导出当前结果；
- 标讯卡片列表；
- 分页、跳页、空状态、加载状态；
- 每条记录进入标讯详情，单位名称进入单位详情。

### 订阅/导出逻辑

- 订阅保存当前关键词、类型、地区、日期和单位条件；
- 订阅支持加载、删除、当前订阅提示；
- 未登录/无权限时应给出登录或咨询引导；
- 导出至少支持当前筛选下的有限条数，文件字段包括标题、类型、地区、单位、供应商、金额、发布时间、来源和原文链接；
- 导出过程中锁定按钮并显示结果反馈。

### 现状与改造

现有 `BidCenter.vue` 已实现上述大部分能力，改造重点是让它成为 `/overview` 的首屏主内容，而不是被“数据中心五合一”外层卡片包裹；补充更多结构化筛选维度时必须同步后端查询参数。

## 5. 标讯详情 `/site/data-center/projects/:id`

### 目标结构

1. 返回、标题、公告类型、行业、发布时间、监控/收藏/查看原文；
2. 基本信息表：编号、地区、项目金额、资金来源、招标方式、分类、资格审查、评标办法、联合体、工期、招标单位、代理机构、建设规模、招标范围；
3. 关键时间线：招标计划、公告、报名截止、文件获取截止、投标截止、开标、开工、竣工；
4. 资金信息：控制价、投资预算、保证金、质保金、资金来源、付款方式；
5. 评标信息：办法、专家、分值构成、定标方式、评定分离；
6. 资质与业绩：公司资质、人员资质、业绩要求；
7. 公告正文与附件；
8. 关联单位：采购人、代理、供应商；
9. 关键词、相似项目、监控/收藏/导出等行动入口。

### GMI 实现原则

现有 `BidDetail.vue` 已有基本信息、时间线、金额/供应商、正文摘要、关联单位和关键词。应增加模块化字段容器，按接口实际返回值显示；无法获得的字段展示“未披露”，不使用脱敏文本冒充真实值。参考地址使用 `projects/:id`，当前 `bids/:id` 兼容路由应保留，并让两种入口落到同一详情组件。

## 6. 单位详情 `/site/data-center/companies/:id`

### 目标结构

1. 企业名、企业标签、法定代表人、注册资本、成立日期、地区、地址、经营状态、统一信用代码；
2. 联系方式与经营范围，支持展开；
3. 经营概况：发包额、发包量、常发包地区、排名；
4. 项目数据 Tab：招标、中标、公示、四库、下浮、商机、拟建、土地、重点项目；
5. 合作企业、联系人、财务/融资；
6. 舆情、信用、司法/经营风险；
7. 工商 Tab：股权、分支、对外投资、变更、高管、集团结构；
8. GMI 差异化：AI 商情报告、公关路径、关系图谱和可追溯证据。

现有 `CompanyDetail.vue` 已具备单位头部、项目/人员/资质/荣誉/开标/诚信统计、AI Banner、单位信息/行业数据/分析报告、关系路径等能力。改造重点是把项目分类和风险/舆情模块视觉上提升为清晰的单位画像导航，并保留后台编辑能力仅在非 portal 模式显示。

## 7. 人员详情 `/site/data-center/persons/:id`

### 目标结构

- 姓名、部门、职位、状态、所属单位；
- 电话/邮箱等联系方式按权限展示；
- 人员编码、证书、专业/职称等速览；
- 参与项目数量与项目轨迹；
- 项目中角色、阶段、加入/退出时间；
- 点击所属单位、项目和“查看人脉”形成关联跳转；
- 无项目时展示空状态和咨询入口。

现有 `PersonProfile.vue` 已具备头部、速览、证书墙、项目轨迹、统计抽屉和人脉入口。需统一官网宽度、颜色和详情页操作语言。

## 8. 情报动态列表 `/site/intelligence`

### 参考结构

- 标题、数据说明和更新时间；
- 总量、地域数、人员节点、平均热度、平均合作概率；
- 多维筛选：关键词、行业、阶段、地区、时间、金额/规模；
- 项目商机卡片：项目名、版本/等级、业主类型、阶段、投资金额、业主、地区、更新时间；
- 商机订阅、导出项目、分页；
- GMI 关系图谱和中标活跃单位榜。

### 现状与改造

现有 `Intelligence.vue` 已有行业/阶段/地域/时间/关键词过滤、商机卡片、图谱节点点击和单位榜。应补充显式“数据总量/当前结果量”、金额口径、业主链接、分页和保存筛选；筛选应从客户端过滤逐步迁移为后端分页查询，以支撑真实大数据量。

## 9. 意向详情 `/site/intelligence/:id`

### 目标结构

1. 项目名称、阶段、行业、地区、发布时间、更新时间、持续跟进状态；
2. 项目概况：工程地区、类型、阶段、投资金额、资金来源、建设周期、建筑面积、建设性质、是否装配式、是否 EPC、地址；
3. 项目动态时间线：立项、设计、施工、竣工验收；
4. 项目描述；
5. 智能分析：概况、进展、资金、业主资信、风险、收益、建设意义、机会；
6. 甲方/设计/承建/分包联系人；
7. 项目相关公告、附件、导出、催更、寻找人脉；
8. 关联单位、人员和路径。

现有 `IntelligenceDetail.vue` 已具备 AI 缓存/异步研判、公告正文结构化解析、附件、联系信息、人脉路径和图谱加载。后续应将“项目概况、项目动态、联系人、智能分析”提升为固定模块顺序，并对字段缺失、AI 超时、无联系人状态提供一致反馈。

## 10. 后端与接口改造清单

优先复用现有接口：

- `/public/home`、`/public/overview`、`/public/intelligence`；
- `/bids`、`/bids/stats`、`/bids/:id`；
- 单位、人员、项目详情及其关联接口；
- `/intent/graph/:id`、`/intent/path/:id`、`/intent-ai/*`、`/intent/winners`。

需要补齐或确认的契约：

- `GET /bids` 支持完整筛选、分页和稳定排序；
- `GET /bids/:id` 返回详情模块所需的结构化字段；
- 意向列表支持服务端分页、行业/阶段/地域/金额/更新时间筛选；
- 首页聚合返回各动态列表的统一字段和 `updated_at`；
- 导出、订阅和监控操作返回明确的权限/失败原因；
- 全部接口统一 `{data, success, message}` 或现有项目约定，避免页面分别猜测响应形状。

## 11. 实施顺序与验收标准

1. 先完成 `/site/data-center/overview` 首屏工作台化和路由语义兼容；
2. 再完善标讯详情和单位详情的模块结构；
3. 统一人员详情与情报列表；
4. 完善意向详情的项目商机模块；
5. 最后调整首页导航、动态流和数据入口；
6. 运行前端类型检查/构建，启动本地服务，逐一访问七类目标地址验证。

验收重点：

- 目标 URL 均能直接打开且刷新不丢路由；
- 列表查询、筛选、分页、订阅、导出可用；
- 项目/单位/人员/意向之间跳转闭环；
- 真实接口失败和空数据不会导致页面崩溃；
- portal 页面隐藏后台编辑操作；
- 移动端无横向溢出，长标题、金额和标签不会互相遮挡；
- GMI 的 AI、人脉、数据流水线能力在关键页面可见且可进入。
