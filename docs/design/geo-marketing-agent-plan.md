# SSM 平台 × GEO：从「招标情报数据中台」到「营销智能体」演进方案

> 2026-08 编制。回答两个问题：
> 1. 现有系统算不算 SEO？—— **不算，但它是 GEO 时代最稀缺的底盘**。
> 2. 能否结合 GEO 做信息采集，最终达到营销智能体程度？—— **能，且分三步走即可闭环**。

---

## 〇、一句话结论

当前系统是**「向内采集」**的招标情报中台（抓别人发布的信息）；SEO/GEO 是**「向外被引用」**（让别人/让 AI 引擎引用我们发布的信息）——方向正好相反，所以严格说它**不算 SEO**。

但 GEO 的本质是「**内容信号工程**」：可验证事实、结构化数据、实体一致性、权威引用。这套系统恰好拥有**别人没有的三样资产**：

| 资产 | 现有实现 | GEO 价值 |
|---|---|---|
| ① 全网采集管道 | web_source + crawl4ai + clue_filter + scheduler | 反手就能采集 **AI 引擎的回答/引用数据**（GEO 监测），无需新基建 |
| ② 行业事实数据 | 招标/中标/意向/业绩/人脉/图谱 | AI 引擎偏好引用**可验证的数据与事实** → 中台数据 = 天然的「被引用弹药」 |
| ③ LLM 管线 | Ollama 筛选/抽取/总结 + AI 人脉分析师 | 直接升级为「内容生产 + 营销分析」Agent |

所以答案不是「能不能结合」，而是**「用哪一半能力先切入」**——见第三章。

## 一、现状定性：这到底算不算 SEO？

### 1.1 方向的镜像关系

```
传统 SEO / GEO（向外）:  生产内容 → 发布到自有渠道 → 被搜索引擎/AI 引擎收录引用 → 获客
本系统现状（向内）:      抓取外部公告 → 筛选/结构化 → 入库 → 图谱/人脉分析 → 服务内部决策
```

- **传统 SEO**：优化关键词、外链、页面结构，目标是搜索引擎结果页排名。
- **GEO（Generative Engine Optimization，生成式引擎优化）**：让品牌/内容被 AI 生成引擎（ChatGPT、Perplexity、Google AI Overviews，国内：百度AI搜索、豆包、DeepSeek、秘塔、腾讯元宝、夸克、天工等）在回答用户问题时**主动引用**。
- 本系统是**纯内向的数据消费方**，没有任何「对外内容出口」，因此既不算 SEO 也不算 GEO。**「信息采集数据中台」这个自我定位是准确的。**

### 1.2 但它是 GEO 时代最稀缺的底座

2025 年末「GEO 爆火、AI 被广告入侵」成为营销行业热点，百度已下场推 GEO 服务（百搜 GEO），腾讯×绝味等案例已跑通「AI Agent 全链路营销」。GEO 行业共识的优化要素是：

1. **可验证事实与数据**（统计、数字、官方信息）→ 恰好是中台最擅长的
2. **结构化标记**（JSON-LD / Schema.org）→ 恰好是动态字段引擎擅长的
3. **实体一致性**（公司/人/项目的统一命名与画像）→ 恰好是 Neo4j 图谱 + company 主数据擅长的
4. **权威信源互引**（被高权重源引用/提及）
5. **多平台分发** + **品牌提及密度**（AI 训练语料与实时检索的可见度）

**结论：方向相反，但地基 80% 通用。** 缺的不是技术，是「对外出口」和「反向监测」这两块新皮。

## 二、GEO 与「信息采集」怎么结合：三种玩法

### 玩法 A：GEO 反采集（监测层）—— 把 AI 引擎变成新数据源 ⭐ 优先落地

把现有采集管道**原样镜像**到「AI 引擎」这个新来源上：

```
[豆包/DeepSeek/秘塔/百度AI搜索/腾讯元宝 对话页]
        ↓ crawl4ai query 模式（复用，需适配渲染/输入框）
geo_query（关键词任务：行业词×公司词矩阵）
        ↓ LLM 抽取（复用 search_llm 的 JSON 抽取容错）
geo_mention（引擎/关键词/日期/回答快照/被引用来源URL/提及实体/是否含本公司）
        ↓ 前端仪表盘（复用 DynamicTable/DynamicForm）
[AI 可见度榜] [竞品引用对比] [高频引用源榜] [回答口径漂移追踪]
```

- 产出物：**「在豆包/DeepSeek 里搜'地质勘查公司'，AI 推荐了谁、引用了哪些网页」**——这是任何传统 SEO 工具都做不到的独家数据。
- 反向价值：高频引用源榜 = **内容生产选题清单**（"AI 总引用这个来源，说明它缺这类内容，我们去补"）。

### 玩法 B：数据资产内容工厂（执行层）—— 让中台数据变成「被引用弹药」

AI 引擎偏好引用**事实、数据、结构化内容**。中台已经沉淀了招标趋势、中标业绩、项目案例、人脉统计等独家事实，把它变成对外内容：

| 中台数据 | 对外内容形态 | 结构化增强 |
|---|---|---|
| 招标/意向统计 | 行业季报《XX省生态修复招标趋势》 | JSON-LD Dataset + Article |
| 中标业绩库 | 公司官网「业绩案例库」页面 | Schema.org Organization/Project |
| 资质/人员/企业画像 | 官网实体页（公司/项目/人员统一命名） | 实体一致性 + sameAs |
| 政策/标准采集 | FAQ 问答页（"地灾治理需要什么资质"） | FAQPage + 权威引用 |
| 项目进度/人脉 | 行业观察长文（AI 分析生成） | 引用真实数据，杜绝幻觉 |

关键动作：**给官网/公众号/知乎/百家号装 JSON-LD 结构化标记 + 保持全渠道实体命名一致**，让 AI 引擎能把「本公司」识别为一个可信实体并引用其事实数据。这是从「被动收录」到「主动引用」的工程化路径。

### 玩法 C：营销智能体（闭环层）—— 从情报系统升级为营销大脑

最终形态是「感知 → 决策 → 执行 → 反馈」闭环：

```
感知层（已有+新增）: 招标采集 + 人脉图谱 + 【GEO 监测】
决策层（新增）:      商机评分 / 内容选题（引用缺口分析）/ 渠道策略
执行层（新增）:      Agent 撰写投标建议、行业报告、官网/公众号/知乎内容 → 人工审核 → 自动发布
反馈层（新增）:      GEO 指标（引用次数、排名、来源数）回流 → 自动迭代选题与话术
```

营销智能体 ≠ 一个聊天机器人，而是**把「发现商机 → 生成内容 → 被 AI 推荐 → 拿到线索」串成自动流水线**。腾讯×绝味「AI Agent 全链路营销较人工组 3.1 倍业绩突破」是这类闭环的行业标杆。

## 三、与现有代码的映射（改造清单）

| 新能力 | 复用 | 新增/改造 |
|---|---|---|
| GEO 监测采集 | `crawl4ai_client.py`（query 模式）、`web_source`、`clue_filter` | `geo_source` 来源配置（豆包/秘塔等）、`geo_query` 任务表 |
| AI 回答解析 | `search_llm.py`（JSON 抽取容错）、`llm_enhance.py` | `geo_mention` 表 + 引用来源/实体提及抽取 |
| GEO 仪表盘 | 前端 DynamicTable/DynamicForm/图表组件 | `GEO 监测` 页面（可见度榜/竞品对比/来源榜） |
| 定时监测 | `scheduler.py`（apscheduler） | 新增 `_job_crawl_geo`（每日一次，串行限速） |
| 内容生成 | `ai.py`（Ollama chat/stream）、`knowledge_extractor.py` | `content_agent`：选题 → 撰写 → 审核 → 发布队列 |
| 实体一致性 | `neo4j_sync.py`、company 主数据、`business_network.py` | 官网 JSON-LD 生成器（Organization/FAQPage/Dataset） |
| 指标回流 | 动态字段引擎 `dynamic_field_engine.py` | geo_mention 统计字段 + 效果对比看板 |

## 四、分阶段路线图（含人天估算）

### 阶段 0：现状（已完成）
招标采集 + 人脉库 + 知识图谱 + AI 分析 —— 即「向内采集」底座。

### 阶段 1：GEO 监测 MVP（约 1~2 周）⭐ 推荐最先做
- [ ] `geo_query` 关键词任务配置（行业词 × 公司词矩阵）
- [ ] 豆包 / DeepSeek / 秘塔 / 百度AI搜索 四引擎采集源（crawl4ai query 适配）
- [ ] `geo_mention` 表 + 引用抽取 LLM 管线
- [ ] GEO 监测页面（可见度榜、竞品对比、高频引用源榜）
- **验收**：能回答「这个月在 AI 引擎里搜『地灾治理公司』，我们排第几、谁在引用什么」

### 阶段 2：数据内容工厂（约 2~4 周）
- [ ] 官网/公众号/知乎/百家号 内容渠道配置（发布队列 + 人工审核）
- [ ] 行业季报自动生成（招标趋势数据 → 报告）
- [ ] JSON-LD 结构化标记生成器（官网实体页 + FAQ + Dataset）
- [ ] 全渠道实体命名一致性（公司/项目/人员）
- **验收**：官网出现「AI 引擎可结构化理解」的实体页与数据页

### 阶段 3：营销智能体闭环（约 4~8 周）
- [ ] 内容选题 Agent（基于 GEO 引用缺口 + 商机评分）
- [ ] 撰写/发布/跟踪自动化流水线（人审闸门）
- [ ] GEO 效果回流看板（引用次数、来源数、线索转化）
- **验收**：一条「AI 引擎出现新商机话题 → 自动出稿 → 发布 → 下周引用量变化」的无人值守链路

### 阶段 4：全链路营销智能体（持续迭代）
- 多 Agent 分工：商机 Agent / 内容 Agent / 投放 Agent / 线索跟进 Agent
- 打通 CRM/投标系统：AI 推荐商机 → 自动生成投标建议书初稿

## 五、关键前提与风险

| 风险 | 应对 |
|---|---|
| AI 引擎反爬 / 条款限制 | 只采集公开对话结果页；低频（每日一次）、串行、限速；评估官方 API |
| 内容被 AI 引用不可控 | 多引擎 + 多平台分散；监测先行，内容后行 |
| LLM 幻觉污染内容 | 内容全部基于中台真实数据生成 + 人工审核闸门 |
| 权威性（EEAT）构建周期长 | 用「独家数据报告」建立差异化，比泛内容更快被引用 |
| 国内平台生态规则变化 | 监测层与内容层解耦，规则变化只影响单渠道 |

**核心假设**（若不符可调整方案）：
- 目标受众 = 政府采购决策者 / 央企总包 / 同行（B2G/B2B），通过 AI 引擎检索行业信息；
- 内容出口以国内渠道为主（官网、公众号、知乎、百家号、今日头条）。

## 六、总结

1. **不算 SEO**——它是内向采集系统，但这正是 GEO 需要的「事实数据 + 采集管道 + 图谱」底盘。
2. **能结合**——最快切入点是「玩法 A：GEO 反采集监测」（1~2 周），把 AI 引擎变成第 N 个数据源，复用 90% 现有代码。
3. **能达到营销智能体**——按「监测 → 内容工厂 → 闭环 Agent」三步走，最终形态是「发现商机 → 自动出内容 → 被 AI 推荐 → 拿到线索」的无人值守营销流水线，这正是行业内「AI Agent 全链路营销」的落地路径。
